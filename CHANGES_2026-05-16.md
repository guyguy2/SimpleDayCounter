## Work completed

### P1-3: R8 enabled in release builds
- `app/build.gradle.kts`
  - Set `isMinifyEnabled = true` on the `release` build type.
  - Set `isShrinkResources = true` to also strip unused resources alongside code.
  - Added `lint { disable += "Instantiatable" }` because `lintVitalRelease`
    runs as part of `assembleRelease` and the `Instantiatable` check is a
    documented false positive for `MainActivity` (which correctly extends
    `androidx.activity.ComponentActivity`, a subclass of `Activity`). This was
    already noted as a pre-existing false positive in the wave-2 entry of
    `IMPROVEMENTS.md`.
  - Added `testOptions { unitTests { isReturnDefaultValues = true } }` so that
    `android.util.Log.d` returns 0 instead of throwing `Method ... not mocked`
    from inside `viewModelScope` coroutines. Without this, the coroutines
    launched by `EventViewModel.deleteItem` / `undoDelete` / `clearRestorationKey`
    silently aborted on the first `Log.d` call, which is why wave-3's tests
    were only "compile-verified" — they all failed at runtime.

- `app/proguard-rules.pro`
  - Replaced the empty default file with explicit keep rules grouped per
    library (Room, Koin, Coroutines, DataStore, Navigation, Compose) plus
    project-specific keeps for `com.happypuppy.daycounter.data.database.**`,
    `com.happypuppy.daycounter.data.repository.DateConverters`,
    `com.happypuppy.daycounter.di.**`, and `EventViewModel`.
  - Kept Room generated `*_Impl` classes (`-keep class **_Impl { *; }`) and
    everything annotated `@Database`, `@Entity`, `@Dao`, `@TypeConverter`.
  - Kept ViewModel constructors via
    `-keepclassmembers class * extends androidx.lifecycle.ViewModel { <init>(...); }`
    so Koin's reflective `viewModelOf(::EventViewModel)` continues to resolve.
  - Preserved line numbers for production stack traces
    (`-keepattributes SourceFile,LineNumberTable` +
    `-renamesourcefileattribute SourceFile`).
  - `-dontwarn` for `org.koin.**`, `kotlinx.coroutines.debug.**`,
    `androidx.datastore.**`, `androidx.navigation.**`, `androidx.compose.**`.

### EventViewModelTest: fixed runtime + added two restoredItemKeys cases
- `app/src/test/java/.../ui/screens/EventViewModelTest.kt`
  - Imported `kotlinx.coroutines.test.runCurrent` and used it after
    `viewModel.deleteItem(...)` to flush the optimistic UI update before the
    pre-delay assertion. `UnconfinedTestDispatcher` dispatches `launch` rather
    than running it inline (a behavior subtlety with
    `kotlinx-coroutines-test` 1.10 when the dispatcher is installed as Main),
    so an explicit `runCurrent` is needed to observe the pre-`delay(200)`
    state inside `deleteItem`.
  - Added test `clearRestorationKey is a no-op when the id is not present`:
    after delete + undo for id=1, calling `clearRestorationKey(999)` must not
    mutate the map. Guards against accidental "remove on absent key"
    side-effects.
  - Added test `undoing the same id twice refreshes its restoration key`:
    two delete + undo cycles for the same item must produce strictly
    increasing restoration-key timestamps so `LazyColumn` re-keys the row
    and re-runs the appearance animation. Without a fresh key the row would
    stay mounted and the swipe-restore animation would not replay.
  - These complement the existing `clearRestorationKey removes only the
    specified id from restoredItemKeys` case.
